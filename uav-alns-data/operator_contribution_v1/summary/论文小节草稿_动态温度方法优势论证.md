# 结果分析小节：动态温度方法的作用机制与性能边界

## 实验设置

为使不同方法之间的比较主要反映动态温度模块的贡献，而非初始解生成方式或参数设置差异，本文统一采用同一 ALNS 求解框架作为基础求解器，并固定电池模型、最大航程、调度起点和温度参考时刻等关键参数。实验数据选取 12 组标准算例，每组算例独立重复运行 5 次，分别构造真实气温下的单平台与多平台两类场景。

在对比方法上，本文设置静态温度基线、仅引入动态温度评估的模型、温度感知修复模型、完整动态温度框架以及不含自适应权重更新的完整动态框架五组方案。这样的分组方式使实验能够依次回答三个问题：动态温度信息是否仅在评价层发挥作用，温度信息进入修复与重构过程后能否形成稳定收益，以及完整动态框架是否已经超过其主要模块消融组。

为避免不同实验组因内部优化目标不一致而造成横向比较失真，本文统一采用统一复评综合成本作为主评价指标。该指标在同一评价器下对各组最优解重新计算总运行成本，综合计入飞行距离成本、航班使用成本、固定成本、温度风险惩罚及不可行惩罚，因此能够更客观地反映不同方法在相同运行标准下的实际表现。

## 关键结果

表1汇总了最能体现动态温度方法优势的关键结果，重点展示真实多平台场景下各动态温度模块逐步引入后的性能变化，以及完整动态框架相对于主要模块消融组的改进情况。为保证不同方法之间的比较具有一致性，本文采用统一评价器对各方法得到的最优解进行复评，并以统一复评综合成本作为主指标，其计算形式为

$$
C_{total} = C_{dist} + C_{flight} + C_{fixed} + C_{temp} + C_{infeas}
$$

其中，$C_{dist}$、$C_{flight}$、$C_{fixed}$、$C_{temp}$ 和 $C_{infeas}$ 分别表示飞行距离成本、航班使用成本、固定成本、温度风险惩罚和不可行惩罚。由于所有方法最终均在相同成本口径下进行复评，表中结果可以直接用于横向比较不同方法的综合调度效果。具体而言，静态温度基线表示在真实天气背景下采用恒定温度近似进行规划的方法；仅引入动态温度评估的模型表示只在目标函数和可行性判断中考虑动态温度，而不改变修复与重构策略；温度感知修复模型表示在动态评估基础上进一步将温度信息用于节点插入和解修复；完整动态温度框架则在此基础上继续引入平台迁移与能量风险修正；不含自适应权重更新的完整动态框架保留全部动态温度模块，但关闭了 ALNS 中基于搜索反馈的算子权重自适应更新机制。

| 比较对象 | 统一复评综合成本 | 相对静态温度基线变化 |
| --- | ---: | ---: |
| 静态温度基线 | 4982.81 | 0.00% |
| 仅引入动态温度评估的模型 | 4834.32 | -2.98% |
| 温度感知修复模型 | 4779.01 | -4.09% |
| 完整动态温度框架 | 4761.07 | -4.45% |
| 不含自适应权重更新的完整动态框架 | 4673.38 | -6.21% |

从表1可以看出，在真实多平台场景下，动态温度模块随着功能逐步增强呈现出较为清晰的性能改进趋势：动态温度评估带来初步收益，温度感知修复进一步扩大收益，而平台迁移与能量风险修正使完整动态框架继续优于主要模块消融组。

## 结果分析

实验结果表明，动态温度方法的收益具有明显的场景依赖性。表1显示，动态温度模块在真实多平台场景下能够形成连续的正向增益，而在真实单平台场景中，完整动态温度框架仍未稳定超过静态温度基线。这说明动态温度机制并未在所有真实气温场景中自动转化为优势，其收益主要体现在多平台协同调度条件下。相较于单平台情形，多平台场景具备更大的任务重分配与路径重构空间，因此更容易放大温度波动对续航能力和调度结构的影响。

进一步的模块级对比表明，动态温度信息只有进入修复决策阶段后，才会稳定转化为可观的性能收益。表1中，“仅引入动态温度评估的模型”虽然已经优于静态温度基线，但收益仍然有限；当温度信息进一步用于节点插入和解修复后，性能改进幅度明显扩大。这说明，仅在目标函数和可行性判断中刻画动态温度，虽然能够带来一定收益，但其作用仍主要停留在评价层。只有当温度信息被用于引导节点分配、路线重构和任务重排时，动态环境信息才真正转化为搜索过程中的有效决策信号。

本轮结果的一个关键变化在于，完整动态方法已经优于其主要模块消融组。表1显示，完整动态温度框架已经优于温度感知修复模型，这表明在温度感知修复之外，平台迁移与能量风险修正模块已经不再只是附加扰动，而是开始与核心修复机制形成正向协同。换言之，完整动态温度框架已经能够在核心应用场景中超过仅保留主要修复模块的简化版本，因此其贡献不应再被理解为单一修复算子的局部改进，而应被视为多个温度感知模块共同作用后的系统性收益。

算子使用统计进一步支持了上述判断。在完整动态温度框架的真实多平台实验中，能量风险导向破坏算子的平均调用次数为 `865.23` 次，温度感知修复算子与温度感知平台迁移算子的平均调用次数分别为 `592.22` 次和 `592.77` 次，局部搜索平均调用约 `86.50` 次。温度相关模块在搜索过程中被持续高频触发，说明完整方法的性能改善并非来自偶然的随机波动，而是来自温度感知算子对解构造与解重构过程的深度参与。结合前述性能变化，可以认为动态温度机制已经由单纯的环境修正项转化为搜索过程中的决策信息。

图3进一步给出了真实多平台场景下温度相关算子的平均调用强度。可以看到，含自适应权重更新的完整动态温度框架显著放大了能量风险导向破坏、温度感知修复与平台迁移算子的调用频率，而不含自适应机制的完整框架在这些算子上的调用水平明显更低，但整体性能反而更优。这一现象说明，当前完整框架已经具备利用温度相关算子形成协同收益的能力，但自适应权重更新对少数温度算子的强化仍然偏强，导致搜索过程出现过度集中。换言之，当前结果更支持“温度相关模块本身有效，但权重调度策略尚未与之形成稳定匹配”的判断。

与此同时，结果也表明当前方法仍存在明确边界。表1中，不含自适应权重更新的完整动态框架仍优于含自适应机制的完整动态温度框架。这说明虽然完整动态方法已经超过主要模块消融组，但当前自适应机制尚未带来稳定的附加收益。结合算子统计可见，自适应开启后温度相关算子的调用频率被显著放大，而关闭自适应时相应调用次数明显更低。由此可以推断，当前限制完整方法进一步提升的主要因素并非温度相关模块本身无效，而是自适应权重更新对少数温度算子施加了过强偏置，导致搜索过程出现过度集中。

综上，当前结果支持以下三点结论。第一，动态温度方法的有效性具有明显的场景依赖性，其优势主要体现在真实气温下的多平台协同调度场景。第二，动态温度信息只有进入修复与重构过程后，才会稳定转化为可见收益，说明该方法的核心价值在于将环境变化转化为搜索决策依据。第三，完整动态温度框架已经优于其主要模块消融组，表明平台迁移、风险修正与温度感知修复之间已形成正向协同；但自适应权重机制仍是当前限制其进一步提升的主要瓶颈。
